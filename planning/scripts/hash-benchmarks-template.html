Method, size formulas and build provenance

Timing method

Construction starts with an allocated empty hash and inserts prepared keys and values one at a time. Input generation, diagnostics and destruction run outside the timer. Small construction batches reuse field names across live hashes. At 4,096 entries and above there is one hash per batch.

Lookup uses a shuffled cycle of successful queries. Query interning happens before timing. Each run targets 200,000 operations and validates key counts, values and a final content digest. All configurations use the same inputs and seeded shuffle.

The seven samples are independent worker processes with three fixed hash seeds rotated across trials. Samples were collected in matched, randomized runs; matching earlier samples are reused with provenance retained.

Confidence bands

Each timing interval is mean ± 2.447 × sample SD / √7: a two-sided Student’s t interval with six degrees of freedom. The critical value comes from the NIST t table.

These bands describe uncertainty in run means on this machine. They assume independent, approximately normal run means. They do not describe individual-operation latency or variation over every possible hash seed. They are pointwise intervals, not a simultaneous confidence band for the entire curve.

Storage curves use layout calculations rather than statistical timing intervals.

Storage formulas

Blead: HV + body + live keys × 24-byte HE + bucket count × 8-byte pointer. The next pointer is included in each HE.

XPerl, linear: HV + body + entry capacity × 16-byte HE. A singleton uses one arena slot; the first heap allocation is two slots in the previous policy and four in the new policy.

XPerl, indexed: HV + body + entry capacity × 16 + metadata + bucket count × index width + entry capacity × link width. This build uses 1-, 2- or 4-byte identifiers without fingerprints.

The previous policy adds its index at the fifth key. The new default adds it at the ninth key; entry capacity then grows from eight to ten.

Matched builds

GCC 13.3, -O2, the same effective C flags and core link libraries, 64-bit integers, system malloc, and threading, multiplicity and debugging disabled. The two XPerl policies above eight keys use the same indexed representation.

Underlying hash outputs and seeded query shuffles were checked to match. The diagnostic extension is compiled against each interpreter’s own headers and runs outside the timers.
